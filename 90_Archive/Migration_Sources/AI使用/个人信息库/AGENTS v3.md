# AGENTS.md

本文件定义长期通用工作规范。

------------------------------------------------------------------------

# 1. 工作原则

1.  先理解业务目标、输入、输出、粒度、唯一键和验收条件，再实现。
2.  优先选择简单、可读、可维护的方案。
3.  不改变未被要求改变的业务逻辑、文件、字段或格式。
4.  关键歧义必须明确指出。
5.  失败、不完整、降级结果必须显性报告。
6.  不把一次性方案包装成长期架构。

------------------------------------------------------------------------

# 2. 语言与注释

-   面向用户说明、代码注释、日志说明默认使用中文。
-   API 字段、代码标识符、库名保留英文。
-   注释解释为什么这样做，而不是逐行翻译代码。
-   复杂函数需要 docstring。

------------------------------------------------------------------------

# 3. 命名规范

Python:

-   变量、函数、模块使用 snake_case。
-   常量使用 UPPER_SNAKE_CASE。
-   类使用 PascalCase。

布尔变量：

-   is\_
-   has\_
-   should\_
-   enable\_
-   allow\_

文件禁止：

-   final
-   new
-   最新版
-   copy

正式版本使用稳定文件名，备份使用时间版本。

------------------------------------------------------------------------

# 4. Colab 与 Notebook 规范

Notebook 结构：

    Controller
        ↓
    Secret Loader
        ↓
    Business Logic
        ↓
    Output

Cell 1 必须集中：

-   项目参数
-   日期范围
-   开关
-   阈值
-   DRY_RUN

默认：

-   不随意创建新 Tab；
-   正式 Tab 固定；
-   同名覆盖；
-   全量替换。

------------------------------------------------------------------------

# 5. Runtime 与 Secret 管理

自动化任务应支持：

-   Google Colab Runtime
-   Local VSCode Runtime

Notebook 不应绑定单一运行环境。

业务逻辑不应该关心 Secret 来源。

------------------------------------------------------------------------

## Secret 来源

Local:

    _Secrets/

通过：

    SECRET_HOME

定位。

Colab:

使用：

    Colab Secrets

规则：

    Colab Secret Name
    =
    Environment Variable Name

------------------------------------------------------------------------

## Secret Loader 原则

推荐：

    Controller
        ↓
    Secret Loader
        ↓
    Business Logic
        ↓
    Output

禁止：

-   Token 写入 Notebook；
-   Token 写入代码；
-   JSON 内容复制到 Markdown；
-   为不同 Runtime 维护两套业务代码。

------------------------------------------------------------------------

## Secret 验收

Secret 配置完成不代表系统完成。

必须验证：

1.  Secret 可以读取；
2.  API 可以认证；
3.  数据读取成功；
4.  数据写入成功；
5.  长任务无需人工介入。

------------------------------------------------------------------------

# 6. 数据处理规范

必须明确：

-   数据源
-   时间范围
-   时区
-   粒度
-   唯一键
-   去重规则
-   汇总口径

处理前验证：

-   输入存在；
-   字段完整；
-   类型正确；
-   日期合理。

------------------------------------------------------------------------

# 7. 测试与验收

状态区分：

    DESIGNED
    IMPLEMENTED
    STATICALLY_VERIFIED
    DRY_RUN_VERIFIED
    LIVE_WRITE_VERIFIED
    BUSINESS_RECONCILED
    ACCEPTED

不能把：

-   Warning
-   跳过
-   部分成功

描述为完成。

------------------------------------------------------------------------

# 8. 安全规则

禁止：

-   上传 GitHub；
-   上传 Google Drive；
-   把 Secret 放入 Obsidian；
-   在聊天中发送 Secret Value。

不记录：

-   密码；
-   Token Value；
-   Private Key。
